## 绳梯标记逻辑优化 — 拒绝短时间大幅度 Y 轴移动

### 问题
`rope_marker_gui.py` 的 `RopeDetector` 只看 8 帧窗口内的总位移 (dx < vx 且 dy > vy)，
不区分这个位移是逐渐爬出来的还是一帧跳出来的。
跳跃、下落、传送 portal 会在 1-2 帧内产生大位移，与真实爬梯在总位移上无法区分 → 误标记。

### 改动
1. 新增 `MAX_FRAME_DY = 10` 常量：单帧 Y 位移超过此值视为跳跃/下落
2. `RopeDetector` 新增字段：
   - `_prev_y`：上一帧 Y 坐标，用于计算单帧 dy
   - `_seg_max_dy`：当前爬梯段内最大单帧 |dy|
   - `rejected_count`：被拒绝的候选数
3. 检测逻辑改进：
   - 每帧计算 `frame_dy`，如果 > `max_frame_dy` → 清空轨迹（防止突变帧污染后续窗口）
   - 爬梯开始时回溯计算窗口内最大单帧 dy
   - 爬梯持续时跟踪段内最大单帧 dy
   - 爬梯结束时校验：`_seg_max_dy > max_frame_dy` → 拒绝记录
   - 爬梯中遭遇脱绳跳跃：用跳跃前数据记录绳梯（不含跳跃帧）
4. UI 新增"跳变>"输入框，可调阈值
5. 状态栏和标记图图例新增 rejected 计数

### 文件
- `rope_marker_gui.py`：RopeDetector 类、UI、start/stop/loop/status
- `test_rope_detector.py`：6 个单元测试，全部通过

### 测试结果
- 真实爬梯 (dy=3/帧) → 记录 1 条 ✓
- 突然下落 (dy=25/帧) → 拒绝 ✓
- 爬梯后脱绳跳跃 (dy=15) → 保留绳梯 ✓
- 传送 portal (dy=40) → 拒绝 ✓
- 边界值 (dy=10=阈值) → 记录 ✓
- 多条绳梯 → 记录 2 条 ✓

## 地图标记工具 — 审阅绳梯预览分辨率提升

### 问题
`map_marker_gui.py` 审阅窗口的绳梯预览图太小、文字模糊：
- `review_and_save` 中 `scale = min(3.0, 500 / max(sw, sh, 1))` → 最多放大 3 倍、最多 500 像素
- `_draw_preview` 始终按原小地图尺寸画图，字体只有 10/8 px
- 缩放用 `Image.NEAREST`（无抗锯齿），边缘锯齿明显
- 保存到磁盘的 `_draw_marker` 也是同样问题

### 修复（根治：直接画高分辨率图，不再"小图 + NEAREST 放大"）
1. `_draw_preview(map_name, ropes, target_size=None)` 新增可选参数 `target_size`
2. 传入 `target_size` 时：创建目标尺寸的画布，所有坐标/线宽/点半径/字体大小都按 ratio 放大
3. `review_and_save`：scale 上限 3.0→6.0, 目标尺寸 500→700
4. `_update_preview` 同步使用 `target_size` 渲染
5. `_draw_marker`（保存到磁盘）同样按 ratio 渲染，输出也是高分辨率 PNG
6. 字体下限：`max(10, int(12*ratio))` / `max(8, int(10*ratio))` 保证清晰

### 效果
- 小地图 154×156 → 预览 691×700（4.49 倍）
- 字体从 8/10 px → 44/54 px，所有文字清晰可读
- 绳梯线粗、端点圆点按比例放大，小地图风格不变

## 地图标记工具 — RopeDetector 重写: 方向感知 + 最小持续时间

### 问题
旧算法用 `abs(dy)`(绝对值)检查 8 帧窗口内总位移, 把"先上后下"的跳跃也当成了持续位移。
用户操作角色的跳跃、碰撞弹开都被误识别为绳梯。

### 核心改动
1. **有符号 dy**: `dy = prev_y - cur_y`, 正=上升, 负=下降
2. **只有持续上升算爬绳**: dy<0 立即终止绳梯段
3. **最小持续时间**: 新增 `min_frames` 参数(默认 10 帧=0.5 秒@20FPS)
4. **停顿超时**: 连续 3 帧 dy=0 → 自动结束绳梯段
5. **`finalize()` 方法**: 循环停止后调用, 强制结束未闭合的爬绳段

### 检测条件(全部满足才记录)
- 单帧 dy >= vy(开始阈值, 默认 2px)
- 持续上升帧数 >= min_frames(默认 10 帧)
- 绳梯段内 x 轴漂移 <= vx(默认 6px)
- 绳梯段内单帧 dy 不超过 max_frame_dy(默认 10px, 排除跳跃帧)
- 去重: 与已有绳梯位置不重复

### 新增常量与 UI
- `VERTICAL_THRESHOLD = 4` → **2**(单帧阈值, 原为 8 帧窗口总位移)
- `MIN_ROPE_FRAMES = 10` (新增)
- UI 新增"持续≥"输入框(`mnf_var`)

### 测试结果(9/9 通过)
- 真实爬绳15帧(2px/帧) → 1 条 ✓
- 跳跃(上3帧+下3帧) → 0 条(rejected) ✓
- 传送(单帧 dy=40) → 0 条 ✓
- 爬绳5帧+被撞弹开 → 0 条(rejected) ✓
- 斜跳(x漂移大) → 0 条(rejected) ✓
- 20帧爬绳(x微漂2px) → 1 条 ✓
- 两条绳梯(12帧+降落后再12帧) → 2 条 ✓
- 爬绳中停顿(dy=0) → 1 条(继续记录) ✓
- 纯静止不动 → 0 条 ✓

## 玩家光点检测 — 改用 R+G 总亮度 (成功)

### 旧算法问题
- 用 `HSV H=[18,40]` 过滤 → 失败
- 黄点和草地都 H=20-30, 区分不开
- 草地 V=170-200, 玩家光点 V=255, 但 HSV 转换有精度损失

### 新算法 (最终)
```python
mask = ((R + G) >= 450) & (R > B) & (G > B) & (R >= 180) & (G >= 180)
```
- **核心: R+G 总亮度 >= 450** (光点=510, 草地=340-400)
- 同时要求 R>B, G>B (黄色调, 排除红/绿物体)
- 候选 area 限制 3-80, aspect ≤ 2.0

### 验证
大大撒旦地图, 玩家光点 RGB=(255, 255, 136), HSV=(30, 119, 255)
- `_find_yellow_candidates`: 1 个候选 (109, 78)
- Tracker 5 帧全部稳定锁定 (109, 78)
- 红色十字精确标在用户红框内 ✓
