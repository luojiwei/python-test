# 平台标记功能 — v3 噪声过滤

## 用户反馈的两个新问题（来自预览图）

### 1. 中间红框：跳跃产生的凸起
**根因**：玩家在平台上跳跃时，y 坐标经历"上升→顶点→下降"的过程，跳过几帧被记录为表面点。RDP 把顶点当成"转折点"保留。

**修复**：
- 新增 `PLATFORM_JUMP_DY = 3`（介于正常斜坡 ≤2 和掉落 ≥5 之间）
- 记录表面时检查 `_dy_history`，若**任何一帧 |dy| > 3**，跳过当前帧的表面记录
- 阈值 3 刚好能覆盖跳跃（dy 通常 4-10），但不影响斜坡（dy 通常 1-2）

### 2. 右侧红框：垂直线段（直角）
**根因**：玩家走过小台阶/边缘时，1-2 帧内 y 突变了 4-5 像素（垂直方向），RDP 把它当成转折点保留，连接起来就成了"垂直线"。

**修复**：
- 新增 `filter_surface_turns()` 后处理函数，在 RDP 之后应用
- 两条过滤规则：
  - **斜率过滤**：转折点的入/出线段与水平方向夹角 > `max_slope_deg`（50°）视为垂直/直角噪声
  - **小凸起过滤**：局部极值点（峰/谷），峰高 < `min_bump`（6 像素）视为跳跃噪声

## 三个可调阈值

```python
PLATFORM_JUMP_DY = 3          # 跳跃过滤阈值（|dy| > 此值跳过记录）
PLATFORM_MAX_SLOPE_DEG = 50   # 斜率上限（度）
PLATFORM_MIN_BUMP = 6         # 小凸起上限（像素）
```

## 验证结果

| 测试 | 结果 |
|------|------|
| 小凸起过滤 | ✓ 峰高 2 像素被滤掉 |
| L 形垂直段 | ✓ 90° 拐角被斜率滤掉 |
| 跳变点 | ✓ 89° 跳变被斜率滤掉 |
| 45° 斜坡 | ✓ 保留（角度 ≤ 50°） |
| 真实斜坡（20-30°） | ✓ 保留 |
| 6 个原始回归 | ✓ 全部通过 |
| 综合用户场景 | ✓ 3 平台干净，无小凸起无过陡 |

**你的"8 转折点水平平台"现在简化为 2 转折点**（端到端直线），跳跃产生的中间凸起和右侧垂直线段都被过滤。
