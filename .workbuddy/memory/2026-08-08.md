## 修复模板匹配崩溃（find_character matchTemplate 越界）

**问题**: 自动脚本在 `perception.py:find_character` 中 `cv2.matchTemplate` 报错：
```
(-215:Assertion failed) corr.rows <= img.rows + templ.rows - 1 ...
```

**根因**: 地图标记工具为"冒险岛怀旧服"窗口标记的 `template_rect` 坐标为 `[743, 1567, 869, 1593]`（对应 4K/高DPI 窗口）。但自动脚本运行时窗口分辨率不同，`frame[1567:1593, 743:869]` 中行切片越界，numpy 返回空数组 `shape=(0, 126)`。`find_character` 中的尺寸检查 `roi.shape[0] < th` 对 `th=0` 无效（0 不小于 0），导致空模板直接被传入 `matchTemplate` 崩溃。

**修复**:
- `map_loader.py`: 模板截取时增加双重边界校验
  1. 坐标越界检测：`ty < 0 or tb > frame_h or tx < 0 or tr > frame_w` → 回退默认 `[85,728,150,745]`
  2. 空模板检测：`th <= 0 or tw <= 0` → 回退默认值
- `perception.py`: `find_character` 增加 `th <= 0 or tw <= 0` 前置返回 None

## PrintWindow 后台截取修复

**问题**: 用 `mss.grab()` 截图，即使 force_foreground 后，游戏仍部分被 WorkBuddy 覆盖（窗口有透明边框/标题栏区域透出底层窗口）。

**修复**: 改用 `user32.PrintWindow(hwnd, dc, PW_CLIENTONLY)` 直接从窗口 DC 抓取，绕过屏幕坐标。无需置顶后置，永远不会被遮挡。

**实现**:
- `capture_window_direct(hwnd)` 函数：`GetDC` → `CreateCompatibleDC/Bitmap` → `PrintWindow` → `GetDIBits` → numpy
- 自定义 `BITMAPINFOHEADER` 结构体（`ctypes.wintypes` 不带 BITMAPINFO）

**结果**: 截图完全干净，仅游戏内容，黄点位置 (32, 128) 准确标出。

**MEMORY.md 新增**:
- 测试/开发脚本截图**优先用 PrintWindow**
- `PW_CLIENTONLY=1` 截的是客户端区域（无标题栏），小地图坐标需对齐

## YOLO 自动标注工具启动失败修复

**问题**: `自动标注工具.bat` 运行 `auto_labeler_gui.py` 时报 `ModuleNotFoundError: No module named 'PySide6'`

**根因**: `yolo` venv（`C:/Users/Administrator/.workbuddy/binaries/python/envs/yolo/`）中未安装 PySide6。

**修复过程**（沙箱限制导致多次尝试）:
1. 直接 `pip install PySide6` → 失败：pip 26.x 的 `safe-delete` 在沙箱内无法访问 Windows 回收站
2. `--force-reinstall` → 失败，且破坏了 pip 自身（`shiboken6` 被卸载后 PySide6_Essentials 写不进去）
3. `ensurepip --upgrade` 修复 pip
4. 手动用 PowerShell `Remove-Item -Force` 清理所有残留的 pyside6 文件和 `.deleteme` 临时文件
5. `pip install --target --no-deps --no-cache-dir PySide6` → 成功安装 6.11.1

**经验**: 在 WorkBuddy 沙箱中安装带大量可执行文件的包（如 PySide6），safe-delete 会在 Scripts/ 和 site-packages/ 都失败。先手动清理残留，再用 `--target` 指定目标目录可绕过 safe-delete 的回收站操作。

## YOLO 标注工具 — DPI 黑边问题修复

**症状**: GUI 截图只占左上 1/4，剩下大片黑色。

**根因**: Qt 把主线程设为 DPI-aware。
- DPI-aware 线程：`GetClientRect` 返回**物理像素** 2732×1536
- DPI-unaware 线程：`GetClientRect` 返回**逻辑像素** 1366×768
- 但 `PrintWindow(PW_CLIENTONLY)` 实际只按**逻辑尺寸**绘制
- 结果：bitmap 2732×1536，PrintWindow 只画左上 1366×768 区域

**修复**: 在 `capture_client` 内用 `_dpi_unaware()` 上下文管理器临时把线程切到 DPI_UNAWARE，让 GetClientRect/bitmap/PrintWindow 都按 1366×768 逻辑像素 1:1 对齐。

**关键代码**: `utils.py:23-50`，使用 `SetThreadDpiAwarenessContext(-1)` 在 with 块内临时切换。

**MEMORY.md 新增**:
- DPI-aware 线程下 PrintWindow + CreateCompatibleBitmap 不匹配，必须切回 DPI_UNAWARE 或用 CreateDIBSection 显式指定像素尺寸
- 调试 GUI 问题时要同时看决策日志和运行日志，不要只看决策日志
