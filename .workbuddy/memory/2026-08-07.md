## 修复自动脚本启动失败

**问题**: 自动脚本启动报 `ModuleNotFoundError: No module named 'tkinter'`

**根因**: yolo 虚拟环境（`C:\Users\Administrator\.workbuddy\binaries\python\envs\yolo`）基于 managed Python 3.13.12 精简版创建，该版本是 nuget/embedded 包，缺少 `_tkinter.pyd`、`tcl86t.dll`、`tk86t.dll` 和 `Lib/tkinter/`。

**修复步骤**:
1. 从 python.org 下载 Python 3.13.14 完整版安装包（`python-3.13.14-amd64.exe`）
2. 静默安装到 `C:\Users\Administrator\.workbuddy\binaries\python\versions\3.13.14-full`
3. 删除旧的 yolo 虚拟环境，用完整版 Python 重建
4. 重装依赖: numpy, opencv-python, mss, ultralytics, onnxruntime 1.24.4 + DirectML, onnx, pillow, requests, onnxslim

**最终验证**: 全部 16 个模块导入通过，onnxruntime 支持 DmlExecutionProvider GPU 加速。

**注意事项**: pip 安装时 safe-delete 机制会干扰文件替换操作，后续如果需要装包，可能需要先手动删除冲突文件或使用 PowerShell 清理。

## 修复 maps同步.bat 双击不工作

## 添加角色名模板标记功能

**背景**: 自动脚本中角色名模板位置写死为 `[85, 728, 150, 745]`，不同窗口可能需要不同位置。

**改动**:

1. **地图标记工具** (`config.py` + `map_marker_app.py`):
   - 新增 `TEMPLATE_RECTS_FILE` 常量 → `marker_output/template_rects.json`
   - 在"巡逻路线"按钮下方新增"模板标记"按钮（新行），点击弹出 cv2.selectROI 框选窗口
   - `_on_template_mark()`: 截屏 → ROI 框选 → 按窗口名保存到 `template_rects.json`

2. **同步脚本** (`sync_maps.py`):
   - 同步 `template_rects.json` 从 `marker_output/` 到 `自动脚本开发/maps/`

3. **自动脚本** (`map_loader.py`):
   - 新增 `_resolve_template_rect()`: 从 `template_rects.json` 按窗口名读取模板区域
   - 优先级: `template_rects.json[窗口标题]` > `template_rects.json["_default"]` > 回退 `[85,728,150,745]`
   - 通过 `GetWindowTextW(hwnd)` 获取当前窗口标题进行匹配

**验证**: 语法检查通过，同步流程测试通过。

## 修复自动脚本 best.pt 缺失报错

**问题**: 自动脚本启动在地铁一号线/大木林1/龙族打猎场时报 `FileNotFoundError: best.pt`，这三个地图只有地图数据没有训练的 YOLO 模型。

**根因**: `discover_maps()` 只检查 `config.json` 存在即列入可选地图，但 `validate_map_resources()` 要求 `best.pt` 必须存在。

**修复**: `discover_maps()` 增加 `best.pt` 存在性检查，没有模型的地图不会出现在下拉列表中，从源头避免报错。

**现状**: 可用地图：东部岩山Ⅵ、射手训练场1、魔法密林南郊（均有 best.pt）。缺少模型的地图需先截图采集 + YOLO 训练后再使用。
