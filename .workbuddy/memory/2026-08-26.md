## 局部滚动小地图解决方案（拼图参考图 + 在线匹配定位）

问题：冒险岛大图的小地图是"局部滚动"模式（只显示完整地图一部分，随角色移动），导致 `find_yellow_dot` 黄点坐标无法直接换算世界模型坐标（缺视图偏移）。

诊断：现有 7 个地图截图（标注工具 screenshots/，1280x720）全部是**整图显示**（黄点大幅移动、相邻帧相位相关平移<2px），旧方案仍有效；滚动问题发生在更大的未采集地图。

用户方案（已实现+验证）：多张局部小地图截图 → 拼接成完整小地图参考图 → 运行时局部小地图在完整图上 matchTemplate 定位 → 视图偏移+黄点 = 世界坐标。

新增 `自动脚本开发/minimap_tools.py`：
- `collect <地图>`：定时截 mm_region 存 `minimap_raw/{地图}/`（Ctrl+C 停），慢速走遍地图保证相邻重叠
- `stitch <目录>`：相邻帧**相位相关**求平移（内容左滚=窗口右移，符号取反）→ 响应≥0.5 直接采信预测位置，响应低才做局部高阈值(≥0.65)校正，失败跳过该帧 → 加权平均叠入画布 → 自动复制到 `maps/{窗口}/{地图}/minimap_full.png`
- `locate_in_full_map`：局部图在完整图上 matchTemplate 定位（自测 18/18、模拟 20/20）
- `compute_world_pos`：视图偏移+黄点 → 世界坐标（按 minimap_size 比例缩放，未配置按 1:1）
- `test`：用废弃都市整图模拟滑动窗口自测拼接+定位（18/18）

集成：
- `map_loader.py`：LoadResult 新增 `minimap_full`/`minimap_size`；load() 读地图目录 `minimap_full.png`（imdecode 中文路径）+ world_model.json 的 `minimap_size`，日志「完整小地图: ...（局部滚动定位模式）」
- `perception_pipeline.py`：`__init__` 加 minimap_full/minimap_size；小地图定位改为：整图模式=黄点即世界坐标；局部滚动模式=locate+compute_world_pos（定位失败保持上一帧）；平台/绳梯判定用世界坐标 wx,wy
- `main.py`：start() 透传 minimap_full/minimap_size

用户操作：重启自动脚本 → 问题地图 `python minimap_tools.py collect <地图名>` 走遍全图 → `python minimap_tools.py stitch minimap_raw/<地图名>` → 重启自动脚本自动加载。地图目录有 minimap_full.png 即启用局部滚动定位，否则回落整图模式。

关键经验：
- OpenCV 中文路径用 `np.fromfile + cv2.imdecode`（imread 返回 None）
- 低纹理小地图上 matchTemplate 全图匹配会误匹配（错误位置 score 也可能>0.3），相位相关对纯平移最可靠
- phaseCorrelate 返回"内容平移"，窗口位移符号相反

## 拼接算法重写：轮廓重叠对齐（修复合成结果不对）

用户反馈"合成出来的小地图不对"，建议按相似轮廓重叠合成。诊断发现真实小地图截图含**固定边框/面板**，相位相关在原始灰度图上被固定元素锁死在零平移 → 所有帧叠一起。

踩坑记录（重要）：
1. **fixed_mask（帧间灰度方差）方案错误**：滚动慢时内容重叠区在相邻帧也几乎相同，std 检测把 89.6% 像素误判为固定 → 内容边缘全被屏蔽 → 拼接失败。
2. **深裁剪 trim 不是越大越好**：trim=8 对无边框数据损失内容边缘（定位 10/18）；**trim=4 甜点**（带边框 9/9、无边框 9/9）。
3. **相位相关响应波动（0.37-0.66）**：0.5 阈值导致半数帧被踢去精修又失败 → **删掉精修分支，相位相关 + 边缘 IoU 验证两步就够**。

最终算法（两处实现一致：`地图标记工具/minimap_stitch_dialog.py` 与 `自动脚本开发/minimap_tools.py`）：
- 每帧 Canny 边缘 + 裁外圈 trim=4（去固定边框）
- 相邻帧裁边边缘图相位相关求平移（符号取反：内容左滚=窗口右移）
- 重叠区域边缘 IoU ≥ 0.12 验证（轮廓重叠不足拒绝该帧，防错拼）
- 加权平均叠入画布（抑制黄点/红点动态元素）

验证：带边框模拟 9/9 放置+定位、无边框 18/18；两实现默认参数 trim=4、min_corr=0.20、min_iou=0.12。
用户需重启标记工具重采集合成；若某地图边框特别宽可调大 trim 参数。

## 角色位置计算完善（拼接/定位统一内容区坐标系）

用户确认合成正确后，完善自动脚本的角色位置计算。关键改动（`自动脚本开发/minimap_tools.py` + `地图标记工具/minimap_stitch_dialog.py` 同步）：

1. **拼接只拼内容区**：叠入画布前先 `frame[trim:-trim, trim:-trim]` 裁掉固定边框，拼接产物不再含"边框散布"，尺寸 ≈ minimap_size - 2*trim。
2. **locate_in_full_map 裁边 + 边缘图匹配**：局部图去边框后，在拼接产物（内容区）上用 Canny 边缘图 matchTemplate（替代原始灰度，抗固定 UI、低纹理多峰），返回"原图左上角在内容区坐标"（ml - trim 还原）。
3. **compute_world_pos 修正为 `view + dot + trim`**：世界模型坐标基于小地图框（minimap_size 含边框），内容区在框内偏移 trim → 世界坐标 = 视图位置 + 黄点 + trim。**不再用 scale 缩放**（scale 在 M 尺寸≠minimap_size 时引入大误差，实测 y 方向可错 40%）。签名保留 full_size/minimap_size 参数（兼容 pipeline），新增 trim=4 默认。

坐标系约定：拼接产物 M=内容区；世界坐标 W 基于框（minimap_size）；W = M坐标 + trim。

验证：无边框自测 18/18 误差 0.0px；带边框模拟 9/9 误差 2.0px。

⚠️ **用户已保存的 minimap_full.png 是旧版（含边框）**，与新的内容区坐标系不兼容，需在地图标记工具**重新合成并保存**一次，再 maps同步.bat。pipeline 调用处无需改动（compute_world_pos 签名兼容）。
