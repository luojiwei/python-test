三项改动：v4.pt 同步到自动脚本 maps/best.pt + 怪物用"怪物类型标签"判定（替代 NON_MONSTER_NAMES 黑名单）+ 角色名从模板匹配改为"YOLO玩家框 + OCR昵称 + 模糊匹配"。

修改文件：

- `自动脚本开发/perception.py`：移除 `find_character`（模板匹配）；新增 OCR 引擎延迟加载（`rapidocr_onnxruntime.RapidOCR`）、`_normalize_name`/`_name_match` 模糊匹配（包含+SequenceMatcher）、`_crop_player_name_roi`（玩家框上方 BGR 裁剪放大）、`_ocr_text`；`detect_monsters` 改用 `MONSTER_CLASS_NAMES` 白名单；新增 `detect_objects`（一次推理拿怪物+玩家）和 `find_character_by_ocr`（玩家框 OCR 模糊匹配）。

- `自动脚本开发/map_loader.py`：`LoadResult` 移除 template/search_region 字段；`load()` 移除整段角色模板截取（截屏+force_foreground+template_rect 越界处理）；日志改输出「怪物类型标签」和「玩家类别」。
- `自动脚本开发/main.py`：`__init__` `self.template/search_region` → `self.char_name`；`start()` 从 GUI `char_name_var` 读角色名传入 PerceptionPipeline；GUI 底部控制行加"角色名"输入框（游戏窗口右侧）；`_save_config`/`_restore_and_trace_config` 持久化 `char_name`。
- `自动脚本开发/requirements.txt`：加 `rapidocr-onnxruntime>=1.2.0`。

环境：自动脚本的 yolo 环境已 `pip install rapidocr-onnxruntime`（含 Shapely/pyclipper 依赖，引擎初始化 OK）。

OCR 调优：`PLAYER_NAME_ROI_ABOVE=48`、`OCR_UPSCALE=4` 是估算默认值，需在实际游戏窗口里根据昵称字号/位置微调（debug_frames/_ocr_*.png 保存了最后一次裁剪图供核对）。注意：v4 玩家检测准确度取决于标注数据，若玩家误检率高于昵称 OCR 成功率，需在标注工具增加"玩家"类样本并重训。
