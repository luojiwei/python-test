# 2026-09-17

## 新建「循环按键脚本」独立工具

新增独立目录 `循环按键脚本/`（不依赖 `自动脚本开发/` 和 `脚本开发工具/`）：
- `main.py`：循环按键脚本
- `启动.bat`：双击启动（沿用 maps同步.bat 的 python 路径写法）

功能：阶段【右】反复执行「Ctrl×3 → 右方向+空格」120 秒 → 阶段【左】同理用左方向 120 秒 → 两阶段无限交替。
另有独立计时线程，每 280 秒依次按一次 1、2、3、4（主键盘数字行）。

关键设计：
- 按键发送自带实现（keybd_event + 扫描码，方向键带 KEYEVENTF_EXTENDEDKEY），与 `自动脚本开发/input_utils.py` 保持一致的按键方式。
- `KeySender` 内部一把全局锁，保证 1/2/3/4 序列不会与 Ctrl / 方向键+空格 交叠。
- 自定义 `Clock` 活动时钟：只累计运行时间，暂停期间冻结（`now()` 用 `_was_paused` 标记跳过暂停区间），阶段循环与 280s 计时器共用同一时钟，暂停后进度不漂移。
- 全局热键用 `GetAsyncKeyState` 轮询：F8 开始/暂停，F9 退出（退出前 `release_all()` 兜底抬键）。
- 带 `--selftest` 离线自检参数：用 `_MockSender` 记录动作区间、缩短时长跑一遍完整逻辑，不产生真实按键；自检日志写入 `selftest.log`，不污染 `run.log`。

### 追加：数字键让位握手

原实现只用 KeySender 的锁串行化，主循环仍可能在 1/2/3/4 之间插入动作。改为主动让位：
- 新增 `NumberGate`（request/ack 两个 Event 做握手）。数字键到点先 `request.set()` 并等 `ack`；
  主循环在「两个动作之间的安全点」（每轮开头、每个 Ctrl 之后）调用 `yield_if_requested()`，
  置 `ack` 后停发按键等待，数字键按完清 `request`，主循环清 `ack` 继续。
- 主循环让位检查放在 `wait_resume()` 之后，暂停期间不会给数字键让位（暂停即全部静止）；数字键 `acquire()` 也等暂停恢复后才按。
- 自检改为记录每个动作的 `(起, 止)` 区间，用区间相交判断是否与数字键序列重叠，实测 0 冲突。

### 追加：开场先按一遍 1/2/3/4

- 3 秒开场缓冲结束后，由 `sequence_worker` 先按一遍 1/2/3/4，再进入阶段循环；
  按完置 `started_event`，`number_worker` 等这个事件才启动，并以 `clock.now()` 为起点
  排后续 280s 周期（即开场那一次算作第 0 次，之后 280s、560s…），避免两个线程在开场瞬间抢跑。
- 自检断言：第一个动作区间必须是数字键序列。

### 追加：修复 启动.bat 乱码

- 现象：双击 bat 报 `'p0"' 不是内部或外部命令`、`'笉瀛樺湪:'`（"不存在"的 UTF-8 字节被按 GBK 解读）。
- 原因：Write 工具写的 bat 是**纯 LF 换行**，而 cmd.exe 按字节偏移解析批处理文件，LF-only 会把行拆错（`cd /d "%~dp0"` 被切成 `'p0"'`）。
- 修复：用 Python 落盘为 CRLF（`Path.write_bytes(text.replace("\n","\r\n").encode("utf-8"))`），与可正常工作的 `maps同步.bat` 一致。
- 验证方式：本机 Git Bash 的 `cmd` shim 已损坏（会起交互式 cmd），改用 Python `subprocess.run(['cmd','/c',...,'--selftest'], input='\n')` 才能真正跑通 bat。

### 追加：加 tkinter GUI（参数可配 + 配置缓存 + F12 开始/停止）

`循环按键脚本/main.py` 重构为 tkinter 界面版：
- 界面：`时间参数`（10 项，全部可配置）/ `运行状态`（状态、阶段剩余、运行时长、距下次数字键）/ `开始(F12)·暂停(F8)·退出(F9)` 按钮 / `日志`（只在滚到底时自动跟随）。
- 配置：`config_cache.json`，`_load_config()` 恢复 + `trace_add("write")` 实时保存，`load_config/save_config` 抽成模块级函数方便自检；启动/退出时也保存。默认值仍是 3 / 120 / 3 / 280 等。
- 热键：`GetAsyncKeyState` 轮询线程 → 命令队列 → `root.after(200ms)` 在主线程消费（不跨线程操作 tk）。F12 开始/停止（停止后重来会重走开场缓冲+开场按键），F8 暂停/继续（计时冻结）。

### 追加：排查「脚本开始后立马又停止」

- 现象：`run.log` 里 `===== 开始运行 =====` → 3 秒后 `开场缓冲结束` → 阶段【右】开始 → 1 秒后 `===== 已停止 =====`，用户以为脚本自己停了。
- 先看完整 `run.log`（不能只看片段）：日志里同一分钟内出现约 10 次「循环按键脚本已就绪」，说明反复启动过；两次「开始/停止」的间隔都是整整 5 秒。
- **受控实验定位根因**（`_probe_f12.py`）：`Popen` 启动 pythonw 应用 → 按 PID 找到标题为「循环按键脚本」的窗口（同进程还有个 34×34 的 `Mode Indicator` 辅助窗口，别抓错）→ `SetForegroundWindow` → `keybd_event` 注入 F12 → 读 `run.log` 增量：
  - 注入 **1 次** F12：正常开跑，不会自停（说明热键边沿检测没问题，一次按键 = 一次切换）。
  - 注入 **2 次**（间隔 5 秒）：日志与用户贴的**逐行完全一致**，包括「阶段开始后 1 秒停止」（= 第 2 次按下发生在第 1 次 +5 秒）。
- 结论：F12 被按了两次 —— 第一次按下后有 3 秒开场缓冲，界面/日志没有任何倒计时反馈，看着像没生效，于是又按一次把自己关掉了。

### 追加：把「一轮实际发了什么按键」量出来（每轮 Ctrl×3 确认）

- 用户反馈「现在是按一下 ctrl 就按一次方向键+空格，我要的是按三下 ctrl 之后再按一次方向键+空格」。
- 先排除「是不是跑到别的旧副本」：全工作区 grep `右方向|Ctrl×|ctrl_count|PHASES`，只有 `循环按键脚本/main.py` 一份实现。
- **量取真实按键流**（`_probe_keys.py`）：`timeBeginPeriod(1)` + 1ms 轮询 `GetAsyncKeyState` 记录 Ctrl/Space/Left/Right 的按下松开沿，按「方向键按下」切分统计每轮前面的 Ctrl 次数。实测（用户当时的 0.1/0.1 配置）：
  ```
  Ctrl 按下 3.735s → 松开 3.841s (+0.106)
  Ctrl 按下 3.948s → 松开 4.057s (+0.107)
  Ctrl 按下 4.168s → 松开 4.276s (+0.109)
  Space+Right 按下 4.386s → 松开 4.494s     ← 一轮 = Ctrl×3 + 1 次和弦
  每轮 Ctrl 次数: [3]
  ```
  即脚本每轮确实发 3 次 Ctrl，问题不在脚本。
- 结论：**目标程序（游戏）把 0.3 秒内的 3 次连按当成一次动作**（动作动画/冷却未结束，后两次落在同一动作里被丢弃），所以游戏里表现为「1 次 Ctrl + 1 次和弦」。
- 处理：① 把 `config_cache.json` 的 `ctrl_gap` 由 0.1 调到 0.5（先给个起点，说明「手速极限」= 游戏一次动作时长，间隔要略大于它）；② 加**每轮动作日志**（`ROUND_LOG_INTERVAL = 5.0`，每阶段第一轮必定记）：`第 1 轮：Ctrl×3（按住 0.1 / 间隔 0.5 秒） → 右方向+空格`，阶段开始行也带上节奏参数，方便用户自己对着日志核对改动效果。
- 改后复测：Ctrl 按住 0.106s、间隔 0.495~0.525s，每轮 Ctrl 次数 `[3, 3]`，`run.log` 出现上面那行每轮日志。
